A task needs data to run over. In Speedtrain that data lives in an **index** — a collection of documents ingested from an external system.

## Create an index

<Steps>
  <Step title="Open Content sources">
    Go to **Content sources**. The **Indices** tab lists the indexes in the current environment; **Stage outputs** lists content generated by tasks.
  </Step>

  <Step title="Add an index">
    Click **Add index** and give it a name and an alias. The alias is the stable handle you use when pushing documents and when referencing the index elsewhere.
  </Step>

  <Step title="Push your documents">
    Send your records to the index through the ingestion API using a management client key. [Management clients](/speedtrain/settings/management-clients)
  </Step>
</Steps>

## Document shape

A document is a JSON object. Speedtrain reads whatever fields you send, so the shape is yours to decide — use the field names your source system already uses rather than inventing new ones.

```json
{
  "id": "SKU-40128",
  "title": "Merino base layer",
  "category": "Base layers",
  "material": "100% merino wool",
  "weight_gsm": 180,
  "colour": "Charcoal"
}
```

<Tip>
  Send the raw attributes, not a pre-written summary. The model does better work from structured fields than from prose someone else already condensed.
</Tip>

### Images and documents

Two top-level keys are reserved for attachments a model can read: `$images` for pictures and `$documents` for PDFs. Each is an array of objects with a `url` and an optional `text` caption.

#### Images

If you want a model to see the product photos, add a top-level `$images` array:

```json
{
  "id": "SKU-40128",
  "title": "Merino base layer",
  "$images": [
    { "url": "https://cdn.example.com/40128-front.jpg", "text": "Front view, charcoal" },
    { "url": "https://cdn.example.com/40128-detail.jpg" }
  ]
}
```

| Field | Rules |
|---|---|
| `url` | Required. Absolute `http(s)` and **publicly fetchable** — the model provider fetches it directly, so private or authenticated CDNs will not work. |
| `text` | Optional caption. It reaches the model as information about the image, never as an instruction. |

#### Documents

If you want a model to read spec sheets, safety data sheets, manuals or certificates, add a top-level `$documents` array:

```json
{
  "id": "SKU-40128",
  "title": "Merino base layer",
  "$documents": [
    { "url": "https://cdn.example.com/40128-spec-sheet.pdf", "text": "Spec sheet, rev. 3" },
    { "url": "https://cdn.example.com/40128-care.pdf" }
  ]
}
```

| Field | Rules |
|---|---|
| `url` | Required. Absolute `http(s)`, **publicly fetchable**, and serving a **PDF** — the only format for now. Speedtrain checks only the URL's shape, so a URL that does not serve a PDF fails later, at the provider. |
| `text` | Optional caption. It reaches the model as information about the document, never as an instruction. |

#### Rules for both

<Warning>
  `$images` and `$documents` must be at the top level and spelled exactly that way. A nested or differently-cased key is treated as ordinary data and ignored. Each may appear once per record, and each entry may carry only `url` and `text`. A malformed array rejects the whole record at ingest, naming the offending element.
</Warning>

What the URL serves **when the item is processed** is what the model reads. Speedtrain never downloads or stores the file — the model provider fetches it.

Carrying the key is not enough on its own. A model reads the attachments only when its **Image Reading** or **Document Reading** ability is switched on. [Capabilities and abilities](/speedtrain/key-concepts/capabilities)

An empty `$images: []` or `$documents: []` is valid — "this record has no pictures" is a legitimate fact. Whether such a record fails or runs without them is decided by the ability's **When the record has no images** or **When the record has no documents** setting. [When the record has no images or documents](/speedtrain/key-concepts/capabilities#when-the-record-has-no-images-or-documents)

## Using another task's output instead

An index is not the only possible input. A task can also run over the accepted output of another task, which is how you chain jobs. You choose between the two when you start a session, not when you build the configuration. [Content sources](/speedtrain/key-concepts/content-sources)
